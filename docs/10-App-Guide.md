> 30-second quiz → 5 weekend recommendations for Jabodetabek + 20-second food quiz → 5 mall tenants.

## 1. Big Picture

**Wikendo** solves one problem: *decision fatigue* — the confusion over what to do each weekend.

There are **2 modes that are completely separate** (their results are never mixed):

| Mode | Route | Input | Output | Quota |
|------|-------|-------|--------|-------|
| 🗺️ **Plan** (place) | `/place` → `/result-place` | 5 questions (~30 seconds) | 5 **place** recommendations | Anonymous 1x (cookie; login 2x production target) |
| 🍜 **Mall** (food) | `/food` → `/result-food` | 4 questions (~20 seconds) | 5 **F&B tenant** recommendations | Anonymous 2x (cookie; login 5x production target) |

Plus 1 directory page (no login, no quota, no LLM):

| Page | Route | Function |
|---------|-------|--------|
| 🏬 Mall directory | `/mall/:slug` | List all tenants of one mall + search & filter + banner to `/food?mall=...` |

**Why a monolith (1 repo)?**
Backend = Nuxt Server Routes + Supabase. There is no separate backend repo because Supabase already acts as the backend (Auth + Postgres + RLS), and the Nuxt server is just a thin layer: guard secrets, enforce quota, call the LLM. Splitting would only be considered if: there is a second non-web client, >10k req/day, or a team of >3 people. (See `docs/02-ADR.md`.)

├── pages/                   # FILE-BASED ROUTING: file name = URL automatically
│   ├── index.vue            #        → GET /
│   ├── place.vue            #        → GET /place        (place quiz, 5Q)
│   ├── result-place.vue     #        → GET /result-place      (place result)

├── server/                  # BACKEND — runs on the server only, secrets are safe here
│   ├── api/
│   │   ├── place/
│   │   │   └── recommend.post.ts        # POST /api/place/recommend
│   │   ├── food/
│   │   │   └── recommend.post.ts        # POST /api/food/recommend
│   │   └── malls/
│   │       ├── index.get.ts             # GET  /api/malls
│   │       └── [slug]/
│   │           └── tenants.get.ts       # GET  /api/malls/:slug/tenants
│   └── utils/
│       ├── db.ts            # supabaseAdmin() — Supabase client using the service key
│       └── llm.ts           # callLLM(), generatePlace(), rankTenants()

**Server route naming rule (important for beginners):**
`recommend.post.ts` = accepts HTTP POST only. `index.get.ts` / `tenants.get.ts` = accepts HTTP GET only.
Wrong method → Nuxt automatically replies 405.

## 4. Setup & Installation

From zero to running on your laptop (5–10 minutes):

```bash
# 1. Enter the app folder
cd wikendo-web-app/app

# 2. Install dependencies (once, ~3 minutes)
pnpm install

# 3. Set up the environment
cp .env.example .env
# → then fill in the real values in .env (see Chapter 5)

# 4. Run the dev server
pnpm dev
# → open http://localhost:3000
```

**Try the main flow:**

1. `http://localhost:3000/` — landing, click 🗺️ or 🍜
2. `http://localhost:3000/place` — answer 5Q → redirect to `/result-place`
3. `http://localhost:3000/food` — answer 4Q → redirect to `/result-food`
4. `http://localhost:3000/mall/grand-indonesia` — directory (needs the Supabase DB to be populated)
5. `http://localhost:3000/food?mall=grand-indonesia` — Q1 mall is skipped automatically (pre-filled from the directory)

> Note: `/result-place`, `/result-food`, and `/mall/:slug` need Supabase + Hermes-combo running.
> Without them, the quiz pages still open, but generating recommendations will error (see Chapter 15).

## 5. Environment Variables

Copy `.env.example` → `.env`, fill in the real values. **The `.env` file must not be committed** (it is already in `.gitignore`).

| Variable | Example | Used in | Notes |
|----------|--------|------------|------------|
| `NUXT_PUBLIC_SUPABASE_URL` | `https://xxx.supabase.co` | Client + server | Supabase project URL. The `NUXT_PUBLIC_` prefix = readable by the browser |
| `NUXT_PUBLIC_SUPABASE_ANON_KEY` | `eyJxxx…` | Client | Anon key (safe in the browser, limited by RLS) |
| `SUPABASE_SERVICE_KEY` | `eyJxxx…service_role` | Server ONLY (`server/utils/db.ts`) | Service-role key — **SECRET, never expose to the client** |
| `HERMES_API_URL` | `http://127.0.0.1:20128` | Server ONLY (`server/utils/llm.ts`) | Local 9Router endpoint; on Vercel replace with the prod URL |
| `HERMES_API_KEY` | `sk-…` | Server ONLY | Hermes API key — **SECRET** |
| `NUXT_PUBLIC_GA_ID` | `G-XXXXXXX` | Client | Google Analytics ID |

**How to read it in code (Nuxt runtimeConfig):**

```ts
// On the server (can access secrets):
const config = useRuntimeConfig()
config.hermesApiKey         // ✅ secret, server only
config.supabaseServiceKey   // ✅ secret, server only

// In the browser/client (public only):
config.public.supabaseUrl   // ✅ allowed
config.public.supabaseAnonKey
```

The env → runtimeConfig mapping is defined in `nuxt.config.ts`.

## 6. Pages

All under `pages/`. **File name = URL automatically** (file-based routing, no manual router config).

### `pages/index.vue` → `/` (Landing, SSR)

Hero "Bingung Weekend Mau Kemana?" + **2 CTAs**: 🗺️ Cari Tempat (`/place`) and 🍜 Lagi di Mall (`/food`).
Static page, good for SSR + SEO.

### `pages/place.vue` → `/place` (Place Quiz — 5 questions, ~30 seconds)

- Concept: **1 screen 1 question** + progress bar + Back button.
- Local state: `step` (question index), `answers` (reactive object), `q` & `progress` (computed).
- Questions: `mood` → `companion` → `budget` → `location` → `time`.
- Done → `router.push({ path: '/result-place', query: { ...answers } })` — answers are sent via the **query string**.
- No fetch here — the quiz purely collects answers in the browser.

### `pages/result-place.vue` → `/result-place` (Place Result)

```ts
const { data, pending, error } = await useFetch('/api/place/recommend', {
  method: 'POST',
  body: route.query   // quiz answers from the URL
})
```

- 3 UI states: `pending` (loading ✨) → `error` (red box) → `data` (5 cards `#1–#5`: name, category, reason 💡, estimated cost, best time).
- The same principle is used by `result-food.vue`.

### `pages/food.vue` → `/food` (Food Quiz — 4 questions, ~20 seconds)

- Q1 `mall_slug` (required: 5 V1 malls) → Q2 `mission` → Q3 `budget_tier` → Q4 `companion` + **Halal-only & Kids-friendly toggles**.
- **Pre-fill:** if opened from the directory (`/food?mall=grand-indonesia`), Q1 is skipped automatically:

```ts
const startStep = (route.query.mall && questions[0].options.some(o => o.value === route.query.mall)) ? 1 : 0
```

- Done → redirect to `/result-food` with the answers + `halal_only` + `kids_friendly` in the query string.

### `pages/result-food.vue` → `/result-food` (Tenant Result)

- POST the answers to `/api/food/recommend`, render 5 tenant cards: badge `[#N]`, `[✅ Halal / ⚠️ Non-halal]`, `[🔥 Hype]`, reason 💡, **📍 Maps** button (Google Maps link + floor info).
- The "results are never mixed" principle: this page **only** renders tenants, no tourist places.

### `pages/mall/[slug].vue` → `/mall/:slug` (Directory — no login/quota/LLM)

- `[slug].vue` = **dynamic route**: 1 file serves `/mall/grand-indonesia`, `/mall/central-park`, etc. (`route.params.slug`).
- Fetch: `useFetch('/api/malls/${slug}/tenants')` + client-side search box (`keyword` + `filtered` computed).
- The gradient banner at the top points to `/food?mall=${slug}` (a bridge from directory → quiz).
- `TenantItem` is defined locally in this file (a compact shape for the list; the full shape lives in `TenantRecommendation`).

### `app.vue` (Global layout)

Header (logo + 🍜 Makan link + 🏬 Mall link) + `<NuxtPage />` (where each page renders) + footer.
Want to add a global navbar/footer? Edit this file, not every page.

## 7. Server API (Backend)

All under `server/`. **Code here is never sent to the browser** — a safe place for secrets & quota.

### `server/utils/db.ts` — Supabase connection (admin)

```ts
export function supabaseAdmin() {
  // singleton: 1 client reused (saves connections)
  // uses config.public.supabaseUrl + config.supabaseServiceKey
}
```

Used by every endpoint that reads/writes the DB. The service key **bypasses RLS** — so input validation & quota must be done in the handler before the query.

### `server/utils/llm.ts` — LLM client (Hermes-combo)

| Function | Input | Output |
|--------|-------|--------|
| `callLLM(system, user)` | 2 prompt strings | string (raw JSON from the LLM) |
| `generatePlace(input: QuizPlaceInput)` | place quiz answers | `PlaceRecommendation[]` (5 items) |
| `rankTenants(input, candidates: TenantRow[])` | preferences + ≤30 candidates from Supabase | `RankResult[]` (5 items: name + reason) |

Cost-saving principle: **filter in Supabase first (free) → the LLM only ranks + 1 sentence of reason**.
The system prompt forces the LLM to reply with **valid JSON only** (no disclaimer) so it can be `JSON.parse`d directly.
15-second timeout, `max_tokens: 2000`, model `hermes-combo`.

### `POST /api/place/recommend` — Generate places

File: `server/api/place/recommend.post.ts`

1. Read the body + set up `session_id` (30-day cookie).
2. Check the anonymous quota: cookie `quota_used === '1'` → 403 `LOGIN_REQUIRED`.
3. `generatePlace(body)` → save to the `generations` table (`quiz_input.type: 'place'`) → set `quota_used=1`.
4. Reply `{ recommendations, quota_remaining: 0 }`.

### `POST /api/food/recommend` — Generate tenants

File: `server/api/food/recommend.post.ts`

1. Read the body (`QuizFoodInput`) + check cookie `food_quota_used >= 2` → 403 `FOOD_QUOTA_EXCEEDED`.
2. Find `mall_id` from `mall_slug` → query `tenants` (`is_open=true` + budget/halal/kids filters, limit 30).
3. Empty → 404 ("Tidak ada tenant cocok. Coba ubah filter.").
4. `rankTenants(body, candidates)` → merge tenant data + LLM `reason` + Google Maps `maps_url` → save `generations` (`type: 'food'`) → quota +1.
5. Reply `{ recommendations, quota_remaining }`.

### `GET /api/malls` — List malls

File: `server/api/malls/index.get.ts`. Returns all active malls (`is_active=true`, sorted by name). No login/quota/LLM.

### `GET /api/malls/:slug/tenants` — List tenants of one mall + filters

File: `server/api/malls/[slug]/tenants.get.ts`.
Query params: `?halal=true` `?budget=budget|mid|splurge` `?kids=true` `?search=kopi` `?mission=long_hangout`.
Column filters are done in Supabase SQL; the `mission` filter (array) is done in memory after the fetch. No login/quota/LLM.

## 12. End-to-End Data Flow

**Plan mode (place):**

```text
[quiz.vue] answer 5Q (browser only)
   │  router.push /result-place?mood=..&companion=..&...
   ▼
[result.vue] useFetch POST /api/place/recommend (body = query)
   │  ┌─ check cookie quota_used → 403 if exhausted
   │  ├─ generatePlace() → callLLM(hermes-combo) → 5 places
   │  └─ INSERT generations {type:'place'} + set cookie
   ▼
render 5 place cards
```

**Mall mode (food):**

```text
[food.vue] answer 4Q + halal/kids toggles (browser only)
   │  router.push /result-food?mall_slug=..&mission=..&...
   ▼
[result-food.vue] useFetch POST /api/food/recommend
   │  ┌─ check cookie food_quota_used → 403 if exhausted
   │  ├─ Supabase: mall_slug → mall_id → filter tenants (FREE, limit 30)
   │  ├─ rankTenants() → callLLM Top 5 ranking + reason
   │  └─ merge tenant data + maps_url → INSERT generations {type:'food'}
   ▼
render 5 tenant cards + Maps button
```

**Directory (no LLM):**

```text
[mall/[slug].vue] → GET /api/malls/:slug/tenants?halal&budget&...
   └─ Supabase directly → tenant list → client-side search
```

## 13. Quota & Limits

| Rule | Current implementation | Production target (see `docs/04-Database-Schema.md`) |
|--------|----------------------|------------------------------------------------------|
| Place 2x/day | Cookie `quota_used` (anonymous 1x → login) | `user_quota` table, reset 00:00 WIB, enforced in the DB |
| Food 5x/day (separate) | Cookie `food_quota_used` (max 2 for anonymous) | `mall_search_quota` table, reset 00:00 WIB |
| Results never mixed | Pages & endpoints fully separate | Same — the contract doesn't change |
| LLM timeout | 15 seconds (`server/utils/llm.ts`) | Same |

> Cookies = a temporary solution for the MVP. Before launch, move to DB quota so it can't be bypassed by deleting cookies.

## 15. Troubleshooting (Common Issues)

| Symptom | Most likely cause | How to check / fix |
|--------|------------------------|----------------|
| `pnpm dev` error `ECONNREFUSED` / result page 500 | `HERMES_API_URL` wrong / 9Router not running | `curl http://127.0.0.1:20128/v1/models` — it must return JSON, not refuse the connection |
| Result 403 `LOGIN_REQUIRED` / `FOOD_QUOTA_EXCEEDED` | Cookie quota exhausted (normal, not a bug) | Open incognito / delete cookies / log in for more |
| Directory `/mall/...` empty | `malls`/`tenants` tables in Supabase not seeded yet | Import `data/tenants-seed.csv` (200 rows) into Supabase |
| `useFetch` 404 at `/mall/:slug` | Wrong slug (check: `grand-indonesia`, `central-park`, `kota-kasablanka`, `pondok-indah-mall`, `aeon-bsd`) | Match it with the `slug` column in the `malls` table |
| `pnpm lint` red `no-explicit-any` | There is an `any` type in the new code | Replace it with an interface from `types/index.ts` |
| Build passes but the page is blank | `NUXT_PUBLIC_*` not filled in `.env` / Vercel env | Check `runtimeConfig.public` in `nuxt.config.ts` against the existing env |
| `nuxt prepare` / TS error after a pull | Stale `node_modules` | `rm -rf node_modules .nuxt && pnpm install` |

## 16. FAQ

**Q: Where is the Nuxt project?**
A: In `wikendo-web-app/app/`. The repo root (`docs/`, `data/`, `design/`) is deliberately kept outside so documentation, seed CSVs, and prototypes don't get mixed with code.

**Q: Why is there no separate backend (e.g. Express/FastAPI)?**
A: A deliberate decision (ADR): Supabase already is the backend (DB+Auth), and the Nuxt server is just a thin layer (secrets, quota, LLM). Building a separate backend repo = +8–12 hours with no user value. Split only if a trigger appears: a second non-web client, >10k req/day, or a team of >3 people.

**Q: Why are the place quiz and the food quiz separate?**
A: Different moments of need (planning at home vs hungry at the mall), different quotas, and the results must not be mixed (owner's decision, Addendum v1.1 LOCKED). A single mixed quiz creates confusion + decision fatigue comes right back.

**Q: What is the LLM used for? How do you keep costs down?**
A: Only 2 things: generate 5 places + rank 5 tenants. The candidate list always comes from Supabase first (free); the LLM never browses/lists from scratch.

**Q: I want to add a 6th mall — what are the steps?**
A: (1) Add a row to the `malls` table; (2) add tenants to `tenants-seed.csv` + import; (3) add 1 option to `questions[0]` in `pages/food.vue`; (4) add 1 entry to `mallName` in `pages/mall/[slug].vue`. No new endpoint needed.

**Q: How do I add a new page?**
A: Create 1 file at `pages/nama.vue` → it automatically becomes the route `/nama`. If it's dynamic: `pages/x/[id].vue` → `/x/apapun`.

**Q: How do I add a new API endpoint?**
A: Create a file under `server/api/...` following the naming pattern (`*.get.ts` / `*.post.ts`), use `supabaseAdmin()` from `server/utils/db.ts` for the DB and `defineEventHandler` + `createError` for the handler.

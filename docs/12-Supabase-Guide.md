# Folder `supabase/` — Mall F&B Database (Phase 8.1)

A guide for **beginners**: what files are here, the order to run them, and how to use them.
Written step-by-step. New engineers read this file first before touching the DB.

> **For AI assistants:** the ground rules are in `app/AGENTS.md`. This file is just a human guide.

## Folder contents

| File | WHAT | When to use |
|---|---|---|
| `migration.sql` | Creates the STRUCTURE: 4 tables (`malls`, `tenants`, `mall_search_quota`, `raw_scrape` staging) + indexes + RLS | Once only (safe to re-run, idempotent) |
| `seed.sql` | Fills the DATA: 5 malls + 200 tenants (40/mall) | After migration; safe to re-run (upsert + delete-insert) |
| `generate_seed.py` | Script that GENERATES `seed.sql` from `../data/tenants-seed.csv` | When the CSV changes (add mall/tenant) → regenerate |
| `tests/test_generate_seed.py` | Generator unit tests (10 tests: mission, quote escaping, bool, NULL tri-state, mall meta) | Whenever the generator/CSV changes → must be green |
| `AUDIT.md` | Valid-vs-survey audit: which fields are trusted, which are queued for survey + query workflow | Before claiming data is verified; every time before an on-site survey |

## How to use (order is MANDATORY)

### 1. Run the migration in Supabase

1. Open your project's Supabase Dashboard → **SQL Editor** → **New query**
2. Copy-paste the **entire** contents of `migration.sql` → **Run**
3. Success if there are no red errors. Tables `malls`, `tenants`, `mall_search_quota` are created.

### 2. Run the seed in Supabase

1. In SQL Editor → **New query** again
2. Copy-paste the **entire** contents of `seed.sql` → **Run**
3. Verify — you should see:

| slug | total_tenant | actual |
|---|---|---|
| aeon-bsd | 40 | 40 |
| central-park | 40 | 40 |
| grand-indonesia | 40 | 40 |
| kota-kasablanka | 40 | 40 |
| pondok-indah-mall | 40 | 40 |

If any count is not 40 → the seed failed, don't continue. Report to Agesta.

### 3. When the CSV changes (new mall/tenant added)

DO NOT edit `seed.sql` manually — it is auto-generated. Do this:

```bash
cd supabase
python3 generate_seed.py   # rewrites seed.sql from the CSV
python3 -m pytest tests/ -q  # must show 10 passed
```

Then re-run `seed.sql` in the SQL Editor as in step 2.

## Why a script instead of hand-written SQL?

The CSV has 3 traps that make the seed fail completely if even 1 slips through:

1. **Apostrophes in names** — `McDonald's`, `D'Crepes`, `Roti'O`. In SQL, `'` must be written as `''`.
   1 slip = 1 failing statement.
2. **Pipe-separated mission** — `quick_bite|family` must become `ARRAY['quick_bite','family']`
   (a `TEXT[]` column, not a plain string).
3. **Bool text** — `true`/`false` in the CSV must become SQL `TRUE`/`FALSE`.

The script + 10 unit tests guard against these. Red test = don't run the seed.

## NULL rule + scrape staging (6 Oct 2026 patch)

1. **Not yet researched = `NULL`, not `FALSE`/empty string.** Empty `halal`/`kids_friendly`/`hype_tiktok`
   → `NULL` + `needs_survey=TRUE` (goes into the survey queue). The halal-only/kids filters
   use `.eq(true)` → `NULL` is automatically excluded. The UI shows ❓ Belum terverifikasi.
2. **Scrapes do NOT go straight into `tenants`.** They land in `raw_scrape` first → city gate
   (non-Jabodetabek = `rejected`) → per-mall parser → clean `tenants`.
3. **Data audit:** `AUDIT.md` — which fields are valid, which are queued for survey (P1/P2/P3).

## FAQ

**Q: Does running the migration/seed twice create duplicates?**
A: No. The migration uses `IF NOT EXISTS`. Seed: malls use `ON CONFLICT DO UPDATE`,
tenants are `DELETE`d per mall first, then freshly `INSERT`ed.

**Q: Where is the `generations` table? Why does the recommend API insert into it?**
A: That's a base-schema table (place quiz, docs/04 section 4) — not part of Phase 8.1.
If your Supabase project is still empty, run that base schema first, then this `migration.sql`.

**Q: Why is the `mall_search_quota` table empty after the seed?**
A: That's normal. The table fills automatically when logged-in users use the food quiz (5/day).
Anon users use a browser cookie (`food_quota_used`, max 2) — they don't touch this table.

**Q: Want to add a 6th mall?**
A: Add 40 rows in the CSV (new `mall_slug`) + add 1 entry in `MALL_META`
(`generate_seed.py`) + regenerate + run the seed. The API + pages follow automatically
(`GET /api/malls` is a dynamic list, the quiz reads from it).
